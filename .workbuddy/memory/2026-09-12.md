# 2026-09-12

## 跑团模拟器项目启动（规划阶段）

用户想做一个"类似于酒馆（SillyTavern）的跑团模拟器"，询问从前期准备到完成的完整步骤。

产出：`跑团模拟器开发蓝图.md`（项目根目录），包含：
- 三个前置决定：规则体系（建议 COC 7th 起步）、玩法形态（建议 AI 当 GM 单人）、模型来源（需做 ModelProvider 适配层）
- 五层架构：表现层 / 编排层（心脏）/ 引擎层 / 数据层 / 接入层
- 核心数据模型：Character、WorldbookEntry、Session（会话树）、GameState、ChronicleEntry、Ruleset
- 提示词编排 11 段顺序（永久层 → 检索层 → 摘要层 → 原文层 → 骰点事实）
- M0-M8 开发里程碑
- 三大难点：数值漂移（铁律：骰子与状态本地权威，AI 只叙事）、上下文爆炸（分层+预算）、记忆一致性（事件日志为真相来源）
- 测试指标与目录结构建议

关键设计主张（后续开发需遵守）：
1. 规则体系做成可插拔 ruleset 模块
2. 随机数与状态由本地引擎权威，模型只输出 narration + state_delta + dice_requests 结构化 JSON
3. Chronide（事件日志）是记忆真相来源，摘要只是索引
4. `core` 包必须纯函数、无 IO、可单测
5. 兼容 SillyTavern Character Card V2/V3 与世界书 JSON

待用户确认：规则体系选型、玩法形态、技术栈偏好。
