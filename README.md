# 跑团模拟器（TRPG Simulator）

> 以玩家为中心的单人 AI 跑团模拟器：上下文编排器 + 规则引擎 + 状态机。
> 灵感来自酒馆（SillyTavern），补上了它最缺的一环——**权威的数值**。
> 纯前端 PWA，一套代码同时跑 PC 和手机，数据全部在浏览器本地。

**现已开源、可在线试玩。** 源码仓库：[github.com/zhyslostland/paotuan-simulator](https://github.com/zhyslostland/paotuan-simulator)；在线地址见下方「在线体验」。纯前端 PWA、无后端，数据全在浏览器本地。

- **规则可插拔**：内置 COC 7th（1d100 百分比）与 DnD 5e（1d20 加值制），并支持自建规则包。
- **题材可切换**：6 个内置题材（克苏鲁 / 东京怪谈 / 二次元 / 粉红团 / 剑与魔法 / 都市异能），题材与规则正交——COC 的百分比也能跑校园日常。

## 快速开始

```bash
npm install
npm run dev        # 打开 http://localhost:5173
```

首次使用点右上角**设置**，填 API 地址 / Key / 模型名（内置 DeepSeek、智谱、通义、豆包、OpenAI、本地 Ollama 六个预设），点「测试连接」确认能通，然后就能开团。

```bash
npm run build      # 产出 dist/
npm run preview    # 预览构建结果
npm test           # 155 个引擎 / 契约测试
npm run typecheck  # tsc --noEmit
npm run demo       # 跑一段无 UI 的引擎演示（tsx src/demo.ts）
```

### 双端使用

| 端 | 方式 |
|---|---|
| **PC** | `npm run dev`，浏览器打开即可 |
| **手机（同 WiFi）** | 手机浏览器访问 `http://<你的电脑IP>:5173`（`vite --host` 已开） |
| **手机（真正独立）** | `npm run build` 后把 `dist/` 部署到任意静态托管，手机添加到主屏即可离线运行 |

已配置 PWA：`manifest.webmanifest` + Service Worker 预缓存，添加到主屏后全屏无地址栏、断网可用（手机端会在有新版本时提示刷新，避免卡在旧版）。

浏览器直连大模型需要服务端允许 CORS。多数国内厂商支持；本地 Ollama 需 `OLLAMA_ORIGINS=*`。

## 怎么玩 · 新手教程

> 应用已开源、可在线试玩（链接见上方「在线体验」）。下面带你在 5 分钟内跑完第一局。Key 已经填好的话，直接从第 3 步开始。

### 🎮 开第一局（5 分钟）

1. **打开并装好**：打开体验链接，手机点浏览器菜单「安装应用」/ 电脑点地址栏「安装」图标，装到主屏。这样断网也能开、也不容易被系统清缓存。
2. **先填 Key**（没填的话）：右上角「设置 → API 提供商」选一家（默认硅基流动），粘贴密钥，点「测试连接」显示成功再保存。没填 Key 之前，点开始只会报「未配置 Key」。
3. **做开局准备**：点右上角「准备」，会看到四个页签（角色 / 同行者 / 世界书 / 模组）加顶上一排「题材 + 规则」选择条。
   - 题材和规则用默认的就好（**克苏鲁 + COC 7th**，百分比骰子，最省心）；想跑校园/奇幻也能换别的题材，规则不用动。
   - 点「**角色**」页签 → 直接点「**套用示例角色**」拿一张现成人物卡；想自己来就手动填，或点「AI 生成角色」写一句设定让它生成。
   - 点「**模组**」页签 → 选一个「内置模组」（和你题材匹配的会标「适配」），或点「**AI 生成模组包**」输入一句话（如「1920 年代新英格兰，一名摄影师在小镇失踪」），甚至勾上「报个名字就开团」直接填《敦威治恐怖事件》这种已出版模组名。
   - 点「**同行者**」页签 → 模组会推荐几个队友候选，挑谁入队（其余忽略）。
   - 「**世界书**」一般不用管，AI 生成模组时会自动写好公开设定。
4. **开团**：关掉准备页，主界面点右上角「**开团**」→ 确认（会清空上一局剧情，但角色/模组/世界书都保留）→ 守密人给出开场白，第一局正式开始。
5. **开始玩**：在「故事」页用大白话写你要做什么，回车发送（不需要任何指令格式）。例如「我推开事务所的门」「我问他女儿是什么时候失踪的」。
6. **要掷骰就点技能**：觉得某件事有风险，在「角色」面板点对应技能（如「侦查」「潜行」）就会弹出检定；写一句「你想怎么做」效果更好。守密人也会主动要求检定——「世界」面板会冒出「掷骰」按钮，一次要多个可以「**一次全掷**」。
7. **卡住了看目标**：忘了该干嘛，点「世界」面板顶部的「**当前目标**」，上面写着你要做什么、失败会怎样、为什么是现在。
8. **随手备份**：玩一会儿后去「设置 → 存档与记录」点「导出存档」，存一份 JSON 到本地（进度只在本机浏览器，换设备不互通）。

> 想停下来下次接着玩？直接关掉就行——进度自动存在本机，重开链接会回到这一局。但换手机/清浏览器前记得先导出备份。

### 🧩 各模块怎么玩

界面是三栏：左「角色」、中「故事」、右「世界」；手机上变成底部三个按钮切换（⌘1 / ⌘2 / ⌘3 也能切）。

- **准备（开局前配置 · 顶栏「准备」）**：四个页签，全都能 AI 一键生成。
  - **角色**：姓名/性别/称呼/描述/性格 + 属性（按规则自动算出血量、理智、魔法值）+ 技能（数值＝成功率）。不会填就「套用示例角色」或「AI 生成角色」；也能「导入酒馆卡 PNG」（只取设定，数值按当前规则重建）。
  - **同行者**：增删队友，调「主动性」（被动/均衡/主动——决定他多爱抢话、多主动），可标记死亡。模组推荐的候选在「按模组推荐的队友候选」里挑谁入队。
  - **世界书**：世界观设定条目，每条有「关键词 + 正文 + 优先级 + 启用」。只在你或守密人**提到关键词时**才注入上下文（全量塞会撑爆记忆），放心加。
  - **模组**：这一局的「故事骨架」——目标三件套（要干嘛 / 失败代价 / 为什么是现在）、篇幅（短/中/长）、开局地点、关键人物与秘密、线索链。可选手内置模组、AI 生成、或贴一段小说/剧本让它整理成卡。**剧透默认隐藏**，要核对再点「显示剧透」。
- **角色（左栏 · 你的状态面板）**：属性与技能按规则降序排列，技能数值就是成功率（越高越好）。顶部「数值条」实时显示 **HP / SAN（理智）/ MP**，掉了会弹「状态变化」卡片提示，不用自己翻。**背包**：点物品看详情；武器有「用此武器攻击」，消耗品有「使用」——数量会真减，用完自动消失。**掷骰**：点技能（左键常规 / 右键困难）弹检定抽屉，可指定难度、对象，并写一句行动描述（写了就「行动+检定合一」）。
- **故事（中栏 · 你和守密人的对话）**：用自然语言描述行动，回车发送；**不需要任何标记或格式**。描述越具体、点到场上的人/地方/线索，目标值越往好的方向走，面板会直接显示改了多少。守密人回复是流式打字机效果；NPC 台词以独立卡片分流，不混进旁白。**回溯 / 重掷**：可退回到某个「关键抉择」重来；「重掷」把上一次骰子重新掷（检定则重掷骰子）。系统一直保留这个能力，不怕走错路。**一键掷骰**：守密人一轮里要求多个检定时会排成队列逐个掷，不会丢；也能「一次全掷」合成一条行动。
- **世界（右栏 · 地图与线索）**：**当前目标**——你要做什么、失败会怎样、为什么是现在，迷失时先看这。**地图节点关系图**：实心＝去过，虚线空心＝只听说过，问号＝不清楚。点地图上的地点只是告诉守密人「我想去那儿」——**去不去得成由剧情决定**（路封了、天黑了都可能被拦下），不会瞬移。守密人带你到图上没有的地方会自动补节点。**场景立绘 / 同行者 / 在地人物 / 线索 / 编年史 / 支线表**：这一局的关键信息全在这，不用去翻聊天记录。
- **设置（顶栏「设置」或 ⌘,）**：**API 提供商 / Key / 模型**——唯一需要你动手的地方；**生图 / 排版 / 音频**——可开场景立绘、调字体大小、开关 BGM 与音效；**存档与记录**——导出/导入存档 JSON、多存档槽、复制对话记录；**预设**——题材+规则+模组+世界书+队友整套打包，可「贴剧本/小说/安科 → AI 读成整套预设」。
- **结档 / 终幕**：这一局**收束**成一段结局正文（不是弹个「你死了」）。结档页上有「回到某个关键抉择」可退回去重来，也能直接「开新团」。主动放弃、求死也可以——引擎直接结算，不会有人劝你回头。
- **帮助（顶栏「?」）**：随时可看的新手说明，内容和上面一致；首次进入会自动弹一次。

## 跑起来 / 部署

本项目是**纯前端 PWA、没有后端**，构建产物就是一堆静态文件，丢到任意静态托管上都能跑。
已配置 `base: './'`（相对路径），同一份 `dist/` 在本地、内网、云托管上都能直接用，不需要按平台改配置。

### 方式 1 · 本机 / 局域网（自用最省事）

```bash
npm install
npm run build
npm run preview     # 监听 0.0.0.0，手机连同一个 WiFi 访问 http://<电脑IP>:4173
```

### 方式 2 · 云托管（在外面也能开）

把 `dist/` 整个目录传上去就行，例如：

- **Netlify**：打开 [app.netlify.com/drop](https://app.netlify.com/drop)，把 `dist/` 目录拖进去，秒得一个链接。
- **Cloudflare Pages**：Direct Upload 同样拖 `dist/`。

> ⚠️ **如果要把链接发给别人试玩**：本应用没有共享密钥，**每个人都要自己去「硅基流动」等平台申请一个免费的 API Key，在「设置」里填好才能对话**。否则打开只能看界面、点开始会报「未配置 Key」。发帖时请务必附上这句话。

### 手机装到主屏

打开链接后：Android/Chrome 走浏览器菜单的「安装应用」，iOS/Safari 走「分享 → 添加到主屏幕」；
也可以直接用应用内「设置 → 安装到设备」里的引导。装好后没有地址栏、断网也能开（PWA 离线缓存）。

## 设计哲学

### t0 —— 以玩家为中心

> **规则退到后台**——只在剧情需要时被唤起，绝不主动冒出来要求玩家操作。
> 前台永远优先回答三件事：**我是谁 / 我要什么 / 我接下来干嘛**。

判断标准很简单：如果某个改动是让规则更精确、却让玩家多一道操作，那它多半是错的。

由此派生的硬约定：

- **模组必须给目标**：`goal`（要达成什么）/ `stakes`（代价）/ `urgency`（为什么是现在）三件套，缺一不可。玩家不知道该干嘛＝守密人失职。
- **战斗轮的回合是给世界用的**：敌人每轮推进一次，玩家在自己窗口内自由描述、不限动作数，绝不写「轮到你才能动」。
- **剧情保密**：真相绝不直接告知玩家；GM 内部资料默认遮罩。

### 第二条 —— 题材与规则正交

- **规则包（Ruleset）** 只管「怎么算」：COC 的 1d100 百分比、DnD 的 1d20+加值、你的自建房规。
- **题材（Genre）** 管「什么味道」：世界观、守密人的写法、生图画风、队友倾向。
- 两者**各自独立可混搭**：用 COC 跑东京怪谈，或用 DnD 跑校园日常，都行。

### 防数值漂移的闭环

模型只输出「意图」（`state_delta` / `dice_requests` / `location` / `summary_delta` / `npc_lines`），
真正的数值计算、边界裁剪、状态合并**全部在本地完成**。模型算的数一律不作数。

```
1. 玩家行动 → 2. 点技能或由模型请求检定 → 3. 本地掷骰 →
4. 结果作为不可更改的事实写进提示词 → 5. 模型只写叙事 →
6. 尾部 JSON 契约解析 → 7. 状态机校验后回写
```

## 架构（五层 · 纯前端）

刻意**不做后端**——这是让手机端能独立运行的前提。所有逻辑在浏览器内，数据存 localStorage + IndexedDB，模型 API 由浏览器直连。

```
表现层   src/ui/*.tsx        React 组件（App / Chat / WorldPanel / CharacterSheet / Preparation / Settings）
编排层   src/orchestrator/   prompt.ts（系统提示词、契约提取、兜底检测）· generate.ts（AI 生成各类卡）
引擎层   src/core/           dice/（骰子）· rulesets/（规则包）· state/（状态机）· genres.ts（题材）
数据层   src/ui/store.ts     zustand 单一数据源 + localStorage 持久化
接入层   src/providers/      model.ts（OpenAI 兼容 SSE 流式 + 生图）
```

`core` 包为纯函数、无 IO、可单测；`store.ts` 是唯一数据源。

## 已实现

**引擎（`src/core`，纯函数、可单测，155 个测试）**

- 骰子表达式：`2d6+3` / `d20` / `d%` / `(1d4+1)*2`；RNG 可注入、可复现；分布枚举（10 万次卡方检验通过）
- COC 7th：六档成功等级、100 必大失败、技能 <50 时 96-99 大失败、难度折算、**奖励骰/惩罚骰**
- DnD 5e 轻量：属性→加值（`toModifier`）、d20 vs DC、优势/劣势
- 状态机：模型只提交 `state_delta`（意图），数值本地算；路径白名单；规则包未定义字段一律拒绝；越界裁剪；非法 delta 只拒绝不抛异常
- 规则包可插拔：实现 `Ruleset` 接口即可加规则；`beginnerGuide`（大白话新手引导）、`starterSkills`（换规则只给 6–9 项起始技能）

**NPC 队友**

同行者是「响应式的存在」，不是自主行动者。每组队友带一个 `initiative` 旋钮：

| 档位 | 行为 |
|---|---|
| `reactive` | 只在被点名或危险逼近时开口（默认） |
| `balanced` | 偶尔主动补一句，但不擅自行动 |
| `proactive` | 会主动提议甚至动手，但重大决定前先征询玩家 |

硬边界（写进提示词，不依赖模型自觉）：不替玩家做重大决策、台词 1-2 句、每回合最多两人发言、只说自己知道的事、关键解谜留给玩家、死亡/离队后不再出现。队友状态走同一套状态机（`companions.<id>.vitals.*`），同样由本地引擎掷骰与裁剪。

**界面**

- 三栏布局（角色 / 故事 / 世界），窄屏自动切底部导航
- **三套主题**：午夜·暗金 / 冷灰 / 羊皮纸（浅色），设置页切换，用 CSS 变量 + `data-theme` 实现，换肤不重建
- **存档与记录**：复制对话记录（纯文本）、导出 / 导入存档 JSON、多存档槽、清空重开
- 流式输出、骰点卡片、成功等级配色、技能点击检定（左键常规 / 右键困难）
- Markdown 渲染

**前期准备（顶栏「准备」按钮）**

开局前配置角色、队友、世界书，三者都支持 AI 生成：

- **角色卡** —— 叙事层（姓名/职业/背景）+ 数值层（规则驱动），可增删改技能，示例角色一键套用，支持酒馆卡 PNG 导入
- **同行者** —— 增改队友，可调主动性（被动/均衡/主动）、标记死亡、编辑性格与数值
- **世界书** —— 条目含关键词、正文、优先级、启用开关。**只在命中关键词时才注入提示词**（`selectWorldbook`），全量塞进去会撑爆上下文
- **模组** —— 含目标三件套、开局地点、地图关系；支持贴任意文本导入成模组
- **预设（Preset）** —— 题材 + 规则 + 模组 + 世界书 + 队友整套打包；**贴剧本/小说/安科 → AI 读成整套预设**；预设可复制/粘贴 JSON 分享、可导出/导入

**分层记忆（防跑偏的关键）**

只保留最近 N 轮原文不够——一个场景往往十几二十轮，早期内容一丢，剧情必然跑偏。上下文分四层：

| 层 | 内容 | 保留策略 |
|---|---|---|
| 永久层 | 规则、角色卡、状态快照、线索 | 从不裁剪 |
| 摘要层 | 远期剧情压缩成的段落 | 全程，400 字封顶 |
| 事件日志 | 每轮一句客观事实 | **从头保留全部** |
| 原文层 | 最近 20 轮完整对话 | 超出即丢弃 |

事件日志是核心：模型每轮通过 `summary_delta` 交出一句客观事实（「谁做了什么、结果如何」），累积起来永不裁剪。日志超 50 条时自动折进摘要层（后台合并，只留最近 20 条明细），合并失败也不致命——日志还在，下次重试。

**游玩**

- 流式叙事 · NPC 台词分流 · 一键掷骰（**一轮多个检定请求会排队，逐个掷，不会丢**）· 回溯 / 重掷
- 战斗轮（轻量回合 + 玩家自由窗口 + 敌人血条）
- **地图节点关系图**（带迷雾 + 缩放拖拽 + 地点名折行与完整名芯片）。点地点发出的是**意图**而非既成事实——守密人若认为此刻去不了，会用剧情里的理由拦下你
- 背包（点击弹窗看详情，武器带伤害；**消耗品按数量扣，用完自动消失**）· SAN 疯狂 / 濒死死亡 · 检定记录
- **状态变化提示**：掉血、拿线索、物品增减、人物登场离场、支线变动会弹一张「状态变化」卡片，不用自己翻角色卡
- **支线表（把网状叙事收敛成有界 2–4 条线）**——GM 每轮维护、引擎持久化、界面常驻

**表现**

- 场景立绘 · 动作小图 · 手绘区域图（大件走 IndexedDB 防丢图）
- BGM（程序化氛围音 + 自配音乐）· 大成功/大失败音效 · 骰点动画

**操作与可靠性**

- 全局快捷键：Enter 发送 / ↑ 取回上条 / Esc 关弹层 / Cmd+1·2·3 切面板 / Cmd+, 设置；触摸设备自动放大按钮热区
- 契约缺失 / 拒绝话术 / 检定泄漏 三类自动重写；网络抖动与流式中断自动重试；图片走 IndexedDB 防丢图；数据久未备份提醒；新手引导

## 更新日志（关键修复）

### 2026-09-14 · 信任地基

修的是"会让人不敢再玩下去"的那一类问题，全部带回归测试（136 → 155）。

| 问题 | 根因 | 修复 |
|---|---|---|
| `3d6` 的期望值算成 14 | 概率分布枚举时 `convolve(dist, dist)` 每轮把骰数**翻倍**，3d6 实际被算成 8d6 | 改为逐个卷积单骰；补 3d6/4d6/5d10 的分布与期望断言 |
| 一轮里要求两个检定，第二个永远掷不到 | 只读了 `dice_requests[0]` | 改成**队列**：全部排队呈现，可逐个掷、可整体忽略 |
| 换成 d20 规则后显示「目标值 +2%」 | 目标值文案写死成百分比 | 统一走 `checkTargetText()`：d100 → `目标值 65%`，d20 → `加值 +2` |
| 子弹永远用不完 | 背包只支持整件 add/remove，`qty` 减不动 | `inventory` 支持按数量增减，减到 0 自动移除 |
| 属性可以填 9999 / 空输入变成 NaN | 输入无上下限，且 NaN 会一路传到派生数值 | 输入加 `min`/`max`，store 端对非有限数回落默认值 |
| 正文里直接写「检定成功/失败」 | 只靠关键词兜底，漏网多 | 提示词新增红线：结论只由界面卡片呈现，正文必须**把结论化成事实**；同时扩大漏网检测 |
| 战斗规则与状态白名单自相矛盾（`combat.*` 被拒） | 契约里的 target 前缀漏了 combat | 补全 `combat.active / round / foes` |
| 编年史折叠后回合号错乱 | 新条目用 `length + 1`，折叠后比已有编号还小 | 改用 `max(turn) + 1`；读档时顺带修正旧档 |
| 旧存档结构升级后打不开 | 没有版本号与迁移 | 新增 `SAVE_VERSION` + `migrateSave()`（只补不删） |
| 长对话越跑越卡 | 流式时整屏消息的 Markdown 全部重解析 | 消息行抽成 memo 组件，回调用 ref 稳定身份 |
| 检定面板把正文糊成一团 | `backdrop-blur` + 半透明底 | 改不透明底并在宽屏收窄 |
| 地图上地名只显示「霍尔特的侦…」 | 侧栏窄，名字硬截断 | 节点名折成两行，图下再给一排完整名字的地点芯片 |
| **地图迷雾失效，开局就能去所有地点** | AI 生成的模组**从未带上** `map_nodes`（提示词要了，UI 没接），于是永远没有"可达关系"，迷雾被整套关掉 | 两条生成路径都接住 `map_nodes`；兜底时按地点顺序串成一条线，不再"没有关系图就取消迷雾" |
| 点地图就能瞬移、想去哪去哪 | 直接把「我前往 X」当作既成事实发给守密人 | 改为发出**意图**，守密人可用剧情理由拦下（时间不够 / 路被封 / 他不知道路），并给一个新的抓手 |
| 摔了一跤掉了血，主页面毫无提示 | 状态是静默更新的 | 每轮把数值/背包/线索/人物/支线/地点的变更翻成人话，弹一张「状态变化」卡片 |
| 手机端不知道能装成 App | 只有 Service Worker，没有安装引导 | 新增「安装到设备」：能弹系统安装提示就弹，不能（iOS）就给分平台文字指引 |
